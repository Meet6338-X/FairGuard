# 📊 visualize.md — the FairGuard data gallery

Every number FairGuard reports starts as a picture-friendly question about the
data. This document walks the **`visualize/`** folder — 100 charts over 11
datasets (plus a drift demo and a text-safety panel) — and explains what each
chart shows, what a *red flag* looks like, and what FairGuard concludes from
each finding.

Regenerate everything with one command (needs no internet, no keys):

```bash
python scripts/visualize_data.py                 # all datasets (~1 min)
python scripts/visualize_data.py --only adult    # one dataset
python scripts/visualize_data.py --only demo_loans --only heart
```

Each dataset gets its own folder, `visualize/<dataset>/`, and the same nine
charts; the browsing index lives at [`visualize/README.md`](visualize/README.md).
The charts are generated by `scripts/visualize_data.py`, which uses the exact
same label/sensitive map as the training scripts — so what you see here is
what FairGuard trains and assesses.

---

## How to read the charts (folder contents at a glance)

| Chart | What it shows | What red flags it catches |
|---|---|---|
| `01_label_distribution.png` | how many rows are positive vs negative | an 80/20-or-worse class balance (models settle for the majority class) |
| `02_numeric_distributions.png` | a histogram grid over the top numeric columns | heavy skew, hard gaps, obviously fake-looking values |
| `03_categorical_counts.png` | bar grid of the low-cardinality categoricals | sensitive groups that barely have any rows |
| `04_label_correlation.png` | signed correlation of every numeric column with the label | a feature **near ±1 with the label** — that is leakage, not signal |
| `05_correlation_heatmap.png` | heatmap of the 15 most label-linked numeric columns | redundant feature blocks, proxy groups |
| `06_missing_values.png` | % missing per column | columns to impute rather than silently drop |
| `07_group_selection_rate.png` | P(label = 1) per sensitive group + group sizes | the raw data is already unfair before any model is trained |
| `08_boxplots_top_features.png` | box splits by label class for the top-6 features | how *separable* the classes are |
| `09_scatter_top_features.png` | the two most label-correlated features, coloured by label | whether a hard linear boundary even exists |
| `10_drift_demo_loans.png` (special) | PSI per feature, `demo_loans` vs the drifted copy | what "distribution shift" looks like on purpose |
| `11_text_safety.png` (special) | heuristic judge score per check for `sample_texts.csv` | what the text panel flags before transformers are installed |

Two rules of thumb this gallery teaches:

- **A **1:1 feature↔label match** is not a good model, it is a leak.** The
  `adult` dataset reports a *perfect* model when it keeps its `income`
  column — which is exactly the RC-23 bug FairGuard now refuses, and the
  reason `04_label_correlation` is the first chart to check of any new CSV.
- **Group selection rates in the data explain the fairness findings.**
  When chart `07` shows two sensitive groups approved at different rates,
  the fairness dimension (`demographic_parity_difference` and
  `equalized_odds_difference`) will back that up after training, not just
  before it.

## Per-dataset chapters

### synthetic demo loans (`demo_loans.csv`, `demo_loans_new.csv`)

- 2,000 rows · label **approved** · sensitive **gender** (+ seeded PII columns
  `email`, `full_name`, `phone`) · both a clean and a deliberately drifted copy.
- Best model: gradient boosting **0.992** hold-out accuracy (random forest
  0.990, logistic 0.948). The synthetic dataset plausibly reaches high
  accuracy; real financial data does not — that contrast is a feature.
- Fairness: equalized odds difference **≈ 0.38** on the hold-out, which is why
  the demo assessment lands at risk **0.73 · High · "Needs review"** once a
  real drift baseline is supplied. The dataset is biased by design so the
  fairness panel has something to catch.
- `[demo_loans/07_group_selection_rate.png]` shows precisely that gap in the
  labels; `[drift/10_drift_demo_loans.png]` shows PSI ≈ 0.30 on
  `income_lakhs` and `credit_score` after the synthetic drift.

### adult (UCI census income)

- 48,842 rows · label **income_gt_50k** · sensitive **sex** · 11 usable
  features after the guard.
- The dataset famously ships the raw target `income` (as `>50K / ≤50K`)
  *next to* its derived label `income_gt_50k`. Once categoricals were kept
  (RC-03), the model could read its own answer → **accuracy 1.000** — the
  perfect red flag. RC-23 now rejects label 1:1 duplicates at feature
  selection, at training, *and again at assessment time* (the report gets a
  ⚠️ leakage section), so the honest hold-out answer is **0.829 · risk
  0.46 → Medium · "Approve with monitoring"**.
- `[adult/04_label_correlation.png]` and `[adult/03_categorical_counts.png]`
  are the charts that exhibit the leak and the sex-based imbalance.

### german credit (UCI Statlog)

- 1,000 rows · label **credit_good** · sensitive **sex** · hold-out accuracy
  0.692 (logistic) / 0.736 (GB/RF).
- Risk **0.65 → High / "Needs review"** with 65 % coverage. The small
  sample means the bootstrap fairness interval is wide — the report shows the
  CI, not just the point estimate, so nobody over-trusts the number.

### taiwan credit default (UCI)

- 30,000 rows · label **default_next_month** · sensitive **gender** ·
  best hold-out accuracy **0.782** (GB). Risk **0.10 → Low / "Approve"** —
  the least alarming dataset in the set.

### bank marketing (UCI)

- 45,211 rows · label **subscribed** · sensitive **age_group** · best hold-out
  accuracy **0.822** (GB). The converter drops `duration` on purpose: it leaks
  the target (call length is only known after the call).

### COMPAS two-year recidivism (ProPublica)

- 7,214 rows · label **two_year_recid** · sensitive **race** · best hold-out
  accuracy **0.675** (logistic).
- The classic ProPublica finding — the model is close to a coin flip and the
  racial disparity is exactly what the fairness panel surfaces. Risk
  **0.47 → Medium · "Approve with monitoring"** on the hold-out split; the
  *fairness* panel, not accuracy, is the story here.

### communities & crime (UCI)

- 1,994 rows · label **high_violent_crime** · sensitive **majority_white** ·
  hold-out accuracy ≈ **0.85**, risk **0.68 → High / "Needs review"**.
- The label itself encodes a racial majority split, so
  `[communities/07_group_selection_rate.png]` is the chart that explains the
  whole assessment: selection rates differ sharply by group (DPD ≈ 0.65).

### heart disease (UCI Cleveland)

- 303 rows · label **disease** · sensitive **sex** · best hold-out accuracy
  **0.868** (GB), risk **0.46 → Medium**.
- Small-sample fairness: 303 rows means the CI matters more than the point
  estimate; the historic diagnosis-rate gap by sex is the fairness finding
  the panel is designed to surface.

### australian credit (UCI Statlog — anonymised)

- 690 rows · label **credit_approved** · sensitive **gender_like** · best
  hold-out accuracy **0.838** (GB/RF), risk **0.46 → Medium · "Approve with
  monitoring"**; the columns are anonymised to names like `X1…X14`, which is
  why chart `03_categorical_counts.png` looks so plain.

### student performance (UCI)

- 1,044 rows · label **G3_pass** (a G3 ≥ pass mark) · sensitive **sex** ·
  best hold-out accuracy **0.908** (all three model types land close).
- 32 usable features — the widest embedding here — so
  `[student_performance/05_correlation_heatmap.png]` shows how quickly the
  one-hot-encoded values stack up.

## The two special charts

### `visualize/drift/10_drift_demo_loans.png`

PSI per feature, `demo_loans` versus its drifted copy `demo_loans_new`.
`income_lakhs` and `credit_score` jump to PSI ≈ 0.30 (major). This is the
picture behind the pipeline rule **"drift needs a different dataset"** — a
self-comparison would draw a flat landscape at exactly 0 for every feature.

### `visualize/text/11_text_safety.png`

Heuristic judge scores per check (`toxicity`, `bias`, `hate_speech`, `pii`)
for `data/sample_texts.csv`. Without `transformers` installed, these are the
offline heuristics that keep the workbench functional; with adapters, the
same panel is occupied by HuggingFace models (see `UPDATE.md` for the plan).

## Glossary — the two-word versions

| Term | In plain words |
|---|---|
| **Hold-out accuracy** | accuracy on rows the model never saw during training |
| **PSI / KS** | two tests asking "does this distribution still look like the old one?" |
| **DPD / EOD** | demographic parity / equalized odds gap — how differently the model treats two groups |
| **Bootstrap CI** | "given this sample size, the honest range of that fairness number" |
| **ECE / Brier** | how much the model's predicted probabilities over- or under-trust themselves |
| **SHAP** | which features pushed the model toward its answer on a given row |
| **Coverage** | how much of the total risk weight was actually assessed in this run |
| **Leakage** | a feature that contains the answer — accuracy becomes fiction |

Deep technical versions of every one of these live in
[`EXPLAIN.md`](EXPLAIN.md); the run-it-yourself commands are in
[`USER_MANUAL.md`](USER_MANUAL.md).
